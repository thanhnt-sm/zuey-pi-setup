# Mode 51 — `--kpi-coeff-approve`

> Finalize coefficient change after PD signs memo (Phase 05 v1.5).
> Validates PD signoff section + Git commit SHA, then applies coefficient mutation.

---

## 1. Trigger

**Flag (canonical):** `--kpi-pending-approve <memo-file>`
**Flag (deprecated alias):** `--kpi-coeff-approve <memo-file>` *(deprecated v1.5.1+, sunset v1.7 — use canonical flag)*

**VN triggers:** "PD đã duyệt hệ số", "apply coefficient change", "chốt đổi hệ số"
**EN triggers:** "approve coefficient change", "apply signed memo"

---

## 2. Required Slots

| Slot | Description |
|------|-------------|
| `memo_file` | Path to PD-signed memo generated by Mode 50 |

---

## 3. Workflow Steps

### 3a. Read memo file + validate signoff
**Alias deprecation check:** If invoked via `--kpi-coeff-approve`, print one-line warning before proceeding:
```
⚠️ --kpi-coeff-approve is deprecated. Use --kpi-pending-approve. (Sunset planned v1.7)
```

Parse memo frontmatter + `## PD Signoff` section. Required fields:
- `Approved by:` (PD name, non-empty)
- `Date:` (YYYY-MM-DD, must be ≤ today, > memo creation date)
- `Signature:` (Git commit SHA full or short — verifiable via `git log --pretty=format:%H -- <memo-file>`)
- Optional: `Conditions:` (free text PD constraints)

If any field missing → abort: "PD signoff incomplete. Required fields: Approved by, Date, Signature."

### 3b. Verify Git SHA (best-effort)
```
sha = parsed signature
if exists '.git' AND command 'git' available:
  result = git cat-file -e {sha} 2>/dev/null
  if result.exit != 0:
    warn: "Cannot verify Git SHA {sha}. Memo accepted but audit weaker."
  else:
    confirm: "Git SHA verified."
else:
  log: "No Git available; signature taken at face value (file integrity only)."
```

### 3c. Match pending entry
Find `ep_history_pending[]` row where `memo_path == args.memo_file` AND `status == "pending_pd_signoff"`.
If not found → abort: "No matching pending entry. Memo may be for older/expired pending."

Pending entry `type` may be: `coeff_delta` (Mode 50) OR `replan` (Mode 56). Both handled below.

### 3d. Apply mutation (branches by entry.type — v1.5 unified approver)
Update kpi-state:

**If entry.type == "coeff_delta":**
1. `coefficients[S|C|R] = new_value` per memo's `coeff_delta`
2. Set `coefficients_changed_at: {today}` (audit field)

**If entry.type == "replan":**
1. `ep_monthly_capacity = entry.new_ep` (or `+= entry.delta`)
2. Recompute milestones per Mode 56 §3f formula (called as utility — NOT re-run Mode 56)
3. Set `replan_applied_at: {today}`
4. Append entry to `replan_history[]` (mirror Mode 56's structure)

**Common to both branches:**
5. Move pending entry → `ep_history[]` with:
   - `status: approved`
   - `approved_by: {PD name}`
   - `approval_date: {date}`
   - `git_sha: {sha}`
   - `memo_path: {file}`
6. Remove from `ep_history_pending[]`
7. **Cache invalidation:** `aggregate_cache.refreshed_at = null` (forces recompute on next read)

### 3e. Recompute downstream
- Recompute PP if month-end has run
- Update next weekly snapshot's Q suggestion baseline
- Flag `schema_dirty = false` (consistency restored)

### 3f. Journal
Invoke `/ck:journal` — entry includes memo path, PD name, Git SHA, coefficient delta.

---

## 4. Outputs

| File | Purpose |
|------|---------|
| kpi-state | Coefficients mutated + ep_history append |
| Memo file | Status header updated to `approved` |

---

## 5. Anti-Pattern Guards

| Guard | Condition | Action |
|-------|-----------|--------|
| Signoff date < memo creation | Suspicious timestamp | Block; ask PM to verify dates |
| Signoff date > 30 days old | Stale approval | Warn; ask if still valid |
| Coefficient outside range | Memo invalid post-edit | Abort with error |
| Self-approval | PD name == PM name | Block: "PD signoff required, not PM self-approve" |
| Memo file modified after signoff date | Tampering risk | Warn + ask PM to confirm |

---

## 6. End-of-Mode Hooks
- `/ck:journal`: YES (milestone)
- Suggest next: `--kpi-track` to recompute signals with new coefficient
